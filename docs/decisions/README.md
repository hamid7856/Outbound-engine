# Architecture Decision Records

An ADR is a short record of an important decision: the context, the decision itself, and its consequences. Add one whenever you change something that is hard to undo or that someone will later ask "why?" about.

Use the template in the handbook repo (`templates/adr.md`). Number ADRs sequentially, and never edit an accepted one. To change a decision, write a new ADR that supersedes the old one.
